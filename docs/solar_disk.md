# Солнечный диск HMI и области NOAA

Точка входа: `app.pipeline.solar_disk_pipeline`. Пример:
`notebooks/00_examples_and_run.ipynb`. Зависимости устанавливаются только через Poetry.

```bash
poetry install
poetry run python -m app.pipeline.solar_disk_pipeline --date 2026-01-20 --time 12:00:00
```

По умолчанию время CLI — 12:00 UTC. `--help` перечисляет параметры. В API
`SolarDiskConfig.requested_time` принимает ISO datetime или `datetime`;
значения без часового пояса считаются UTC, явные смещения переводятся в UTC.
Для даты без времени в API укажите полдень явно: `2026-01-20T12:00:00Z`.

`build_solar_disk(config)` возвращает `(Figure, WCSAxes)`.
`prepare_solar_disk(config)` возвращает `SolarDiskData` для конструктора или
`plot_solar_disk_on_ax(ax, data)`. Ось создаётся с `projection=data.solar_map`.
`build_solar_disks(configs)` строит `1 × N`, возвращает `(Figure, list[WCSAxes])`;
`figsize` задаёт размер каждой панели, первая конфигурация определяет имя файла,
каталог, DPI и необходимость сохранения общей фигуры.

Параметры конфигурации:

| Параметр | По умолчанию / назначение |
| --- | --- |
| `source_id` | 18; этот продукт поддерживает только HMI Int |
| `max_time_delta_minutes` | 30; ограничение разницы времени запроса и кадра |
| `annotate_active_regions` | `True`; при `False` SRS не загружается |
| `force_download` | `False`; использовать локальный кеш |
| `allow_srs_fallback` | `True`; разрешить архивное зеркало SolarMonitor |
| `download_base_dir`, `plots_base_dir` | `files`, `results` |
| `figsize`, `dpi` | `(9, 9)`, 300 |
| `filename` | `Solar_disk_<HHMMSS>.png` |
| `label_offset`, `label_fontsize` | `(9, 10)` пунктов, 11 |
| `colorbar`, `save` | `False`, `True` |

## Источники и кеш

1. [Helioviewer API v2](https://api.helioviewer.org/docs/v2/api/index.html):
   `getClosestImage`, `getJP2Image`, при необходимости `getJP2Header` по ID кадра.
   JP2 — промежуточное изображение Helioviewer, не исходный научный FITS.
   Значения пикселей подходят для визуализации, а не абсолютной фотометрии.
2. [Официальный архив NOAA/NCEI SRS](https://www.ngdc.noaa.gov/stp/space-weather/swpc-products/daily_reports/solar_region_summaries/):
   `<год>/<месяц>/<YYYYMMDD>SRS.txt`. Загружается отчёт на фактическую дату кадра.
3. Резерв: архивный NOAA SRS на SolarMonitor:
   `https://www.solarmonitor.org/data/YYYY/MM/DD/meta/MMDDSRS.txt`
   (например, `0120SRS.txt`). Переход происходит
   только после ошибки основного источника и сопровождается предупреждением.
   Дата выпуска обязательно сверяется; текущий `srs.txt` никогда не используется.

Кеш: `files/<дата запроса>/solar/`: JSON выбора кадра, JP2 по ID, XML WCS,
исторический SRS и JSON его происхождения. Нет необходимости дублировать эти
небольшие продукты в HDF5. Запросы последовательные, с таймаутами подключения
15 с / чтения 90 с и максимум тремя повторами с backoff для временных ошибок.
Проверяются HTTP-статус, MIME, размер, декодирование JP2 и размерность кадра.

В `files/<дата>/solar/` сохраняется JSON с фактическим источником SRS и его URL, ID HMI,
точным временем наблюдения, эпохой WCS, исходными строками NOAA и полученными
координатами всех видимых областей. При повреждённом кеше используйте
`force_download=True` / `--force-download`.

## Координаты и изображение

Используется раздел I SRS — области с пятнами. Разделы IA (плажи без пятен)
и II (ожидаемое возвращение областей) исключены. Полные номера после
15 июня 2002 года восстанавливаются добавлением 10000 к четырёхзначным номерам,
согласно соглашению парсера SunPy; уже полные номера не изменяются.

Северная широта и западная Stonyhurst-долгота положительны:
`N15E20 → (+15°, −20°)`, `S11W35 → (−11°, +35°)`.
Нули и пробелы внутри полей допустимы. Эпоха берётся из `Locations Valid at`,
а не из времени публикации. Запись `19/2400Z` в выпуске 20 января означает
20 января 00:00 UTC; переходы месяца и года учитываются.

`sunpy.physics.differential_rotation.solar_rotate_coordinate` переносит
Stonyhurst-координаты по модели Howard (сидерическое дифференциальное вращение)
к наблюдателю из HMI WCS. Изменение положения наблюдателя учитывает SunPy.
Далее `SkyCoord.transform_to` даёт helioprojective X/Y, а `world_to_pixel`
определяет положение подписи. `is_visible` исключает обратную сторону Солнца;
невалидные строки и координаты пропускаются с предупреждением.

SunPy HMI использует `T_OBS` (середину экспозиции) как эпоху WCS. Заголовок
показывает `DATE-OBS` (начало наблюдения), округлённое до секунды; JSON сохраняет
обе точные эпохи. Не следует интерпретировать `T_OBS` с суффиксом TAI как UTC.

При наличии backend Glymur/lxml используется штатный reader SunPy. В текущей
Poetry-среде JP2 уже читает Pillow/OpenJPEG, поэтому дополнительный декодер
не установлен: данные читаются Pillow, XML — через `getJP2Header`, затем создаётся
SunPy Map. Строки JP2 переворачиваются по вертикали точно так же, как в reader
SunPy. CRPIX/CRVAL/CDELT, CROTA/PC и параметры наблюдателя берутся из заголовка;
масштаб `getClosestImage.scale` для визуального API не подменяет WCS CDELT.

Фон за лимбом маскируется по WCS и `RSUN_OBS`. Нормализация использует
99,8-й процентиль яркости диска. Смещение подписей задаётся в пунктах;
автоматическое разнесение меняет только текст, не координаты областей.
Точность ограничена округлением и суточной частотой SRS и эволюцией областей:
это местоположения групп, не измерение центра каждого отдельного пятна.

- Запрос: `2026-01-20T12:00:00Z`.
- Helioviewer ID: `183899217`, JP2 4096 × 4096.
- `DATE-OBS`: `2026-01-20T11:59:37.600Z`, отклонение 22,4 с.
- API/заголовок графика: `2026-01-20 11:59:38 UTC`.
- Эпоха WCS: `2026-01-20T12:00:00.099Z` (преобразовано из TAI).
- [Использованный официальный SRS](https://www.ngdc.noaa.gov/stp/space-weather/swpc-products/daily_reports/solar_region_summaries/2026/01/20260120SRS.txt):
  выпуск 00:30 UTC, координаты на 00:00 UTC, 10 областей с пятнами.
- PNG: `results/2026-01-20/Solar_disk_120000.png`.
- Метаданные: `files/2026-01-20/solar/Solar_disk_120000.json`.

Визуально сверены 14341 (южнее центра), 14342 (севернее центра), 14347
(северо-восточная часть диска), 14349 (у юго-восточного лимба) с независимым
[SolarMonitor HMI 20 января, 19:34:29.900 UTC](https://www.solarmonitor.org/data/2026/01/20/pngs/chmi/chmi_06173_fd_20260120_193429.png).
Более поздняя картинка закономерно показывает западное смещение групп.
SolarMonitor также подписывает 14340 и 14346, которые в SRS относятся к
разделу IA и потому здесь не включены. Индивидуальная подгонка координат
не выполнялась. Контрольная картинка сохранена в `files/2026-01-20/solar/reference/`.

Для проверки кода:

```bash
poetry run ruff format --check app/solar app/pipeline/solar_disk_pipeline.py app/visualization/solar_disk_plotter.py
poetry run ruff check app/solar app/pipeline/solar_disk_pipeline.py app/visualization/solar_disk_plotter.py
```

Тестовые файлы не добавлялись по условию задания. Основная проверка — реальная
загрузка и визуальный контроль изображения, затем повторное построение из кеша.
Повторный запуск с программно запрещёнными HTTP-запросами успешно построил диск
и панель `PlotConstructor`; кешированные файлы остались неизменными. Также
построена фигура для 20 и 21 января: `solar_disks_20260120_20260121.png`.
Проверены знаки E/W, нули и пробелы, переходы месяца/года, пропуск повреждённой
строки, исключение обратной стороны Солнца и отказ при допуске времени 0,1 минуты.
Официальный SRS и резервная копия SolarMonitor дают одинаковые записи.
